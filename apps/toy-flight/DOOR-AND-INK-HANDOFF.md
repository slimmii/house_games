# Door, storage and ink handoff — 4 October 2026

> Written before the monorepo split: house code, assets and pipeline scripts now live in [packages/house](../../packages/house/README.md), Blender sources in [models/](../../models) (formerly `output/blender`), and the tower defense in [apps/tower-defense](../tower-defense/README.md). Paths in the prose and tables are as they were in the original `toy-flight/` app; the command blocks have been updated for the new layout.

This document describes the current door/storage review and ink overhaul. The source of truth is the checked-in TypeScript and generated manifests. The canonical Blender scene is read-only during this work. Changes have not been deployed to `drone.assimilate.be` by this task.

## Requested behavior

- Outside: aim at a room door, cupboard handle, drawer pull or garage control within 2.4 game units and press **G**. After using a cupboard, looking away and pressing G again closes that same cupboard while nearby.
- Inside storage: G toggles the current compartment open **and closed**, with no visible handle, previous interaction or valid aim packet required. Pressing it during movement reverses the group intent.
- Inside drawers: the server carries an eligible occupant with the tray in either direction. Obstacles and other pilots pause the motion. Enclosing wardrobe leaves wait for inner drawers to retract before closing.
- Hinges ease into their end positions. Mirrors use separated bypass rails; the veranda panel first unseats, then travels sideways. The garage uses twelve articulated sections on an inward overhead track with a visible motor and guides.
- Ink remains unlimited. The visual direction is a rapid ink shooter with visible blobs, organic glossy patches, impact droplets and responsive feedback. This remains the existing drone game; no ammunition tank or new team/scoring mode was requested.

The visual reference was Nintendo's [Splatoon weapons overview](https://splatoon.nintendo.com/en/weapons/). All ink geometry and effects here are generated by the application; no Nintendo assets are used.

## Architecture and ownership boundaries

| Area | Main files | Important invariant |
| --- | --- | --- |
| Door inventory | `src/shared/doors-manifest.json`, `closets-manifest.json`, `scripts/export-doors.py`, `closet-inventory.mjs` | Stable IDs and array ordering identify the same assembly on server and client. |
| Motion | `src/shared/door-motion.ts`, `door-types.ts`, `doors.ts` | One rigid pose per component drives rendering, collision, ray targeting, rider displacement and attached ink. Never implement a separate client-only animation. |
| Storage structure | `src/shared/closet-interiors.ts`, `src/client/closets.ts` | Authored boards remain authored; replacement shells, shelves and tray geometry share their collision description. |
| Interior controls | `src/shared/closet-escape.ts`, `src/server/simulation.ts`, `src/client/main.ts` | The authoritative server resolves containment and group intent; the HUD uses the same resolver. |
| Aimed controls | `src/shared/interaction.ts` | Cover, reach, exact grip volumes and the server's recent displayed-pose history all participate in validation. |
| Moving ink | `src/shared/paint.ts`, `protocol.ts`, `src/client/paintBatch.ts` | Store attachment position/normal in closed-world coordinates plus door ID and optional sectional `partIndex`. |
| Ink authority | `src/server/simulation.ts`, `src/shared/aim.ts` | The server decides impacts and tags. Camera aim never bypasses cover between the drone's muzzle and target. |
| Ink presentation | `src/client/paintBatch.ts`, `projectileBatch.ts`, `inkEffects.ts`, `main.ts` | Reuse bounded geometry/particle pools, clip patches to their supporting face, and distinguish new impacts from late-join history. |

There are 144 door definitions: 14 room assemblies (including a fixed veranda assembly) and 130 storage fronts across 72 units. Of the storage units, 36 retain their exact authored structure and 36 reconstruct removed solid carcasses as hollow storage. Appliances and existing open shelving are separately inventoried and are not silently converted into cupboards.

### Motion details to preserve

`DoorState.fraction` is the normalized animation clock, and `opening` is its target direction. Shared easing converts that clock to physical pose. Ordinary motions take 1.1 seconds, the top-hinged laundry flap 1.3 seconds, tracked slides 1.6 seconds and the garage 2.8 seconds. Do not calculate drawer displacement as `slide * fractionDelta`: easing requires the difference between the two actual shared poses. Shared component rotations apply in X → Y → Z order; preserve all three axes when transforming ink vertices and normals.

Garage part indices run from bottom to top and remain stable while opening. A hit on one part must retain that part index through server snapshots, late joins and rendering. The original garage finish has no UV texture; generated sections reuse the authored graphite and seal materials. The source monolithic leaf is hidden when the sectional assembly is used.

The inside resolver treats the selected fronts as a group. Sliding pairs stack to create a usable exit instead of swapping positions and blocking the same opening. A nested drawer includes the surrounding fronts. Closing is sequenced so the outer leaf cannot cross an extended inner drawer. Rider movement and tray movement are accepted or stopped together.

### Review findings corrected

- Generated carcass boards used to extend through the thickness of the closed door. Generated structure now stops behind the inner front face with a 0.01 game-unit reveal; logical containment and retained authored boards are unchanged.
- Blind kitchen and laundry corners needed clearance in the perpendicular unit, beyond merely removing the shared side board. Curated corner relief is generated identically for visible geometry and collision. Stepped floor/top closure boards preserve the exterior shell above and below the neighboring leaf's sweep; the relief must never become a hole through the cupboard.
- The sink corner leaf uses an 85-degree stop. Camber bench drawers 2–5 use calibrated travel stops around the dining table's steel frame (`closet_018`: 0.85, `019`: 1.0, `020`: 0.9, `021`: 0.85 game units).
- The laundry overhead flap (`closet_056`) lifts about its top edge. The adjoining upper doors (`057`, `058`) use an overlay hinge axis ahead of the retained niche cheeks.
- Bathroom mirrors now occupy permanently separated bypass rails, offset 0.04 and 0.16 game units from their authored plane. A closed-pose `baseOffset` is part of the shared transform. Testing both leaves at the same fraction missed intersections: the regression now checks 101 × 101 independent pose combinations, including handle geometry. The existing bedroom wardrobe lanes remain intact, and veranda unseating is preserved.
- Attached ink retains the entire patch silhouette and surface normal on hinges, drawers, sliders, the top flap and individual garage sections. Edge clipping also applies to highlights and detached droplets.

### Ink behavior and capacity

`src/shared/ink.ts` defines the 0.125-second firing interval, 72-projectile cap, 600-mark history and impact size range. Firing cadence retains fractional tick timing instead of rounding each interval upward. After a pause, firing restarts with one shot, without a catch-up burst. Projectile speed remains 90 game units/second and lifetime 2.4 seconds to preserve established crosshair aiming.

The paint mesh uses a 32-bit index buffer, deterministic organic patches, glossy normals, subtle rims and clipped droplets. More recent color draws over older color while normal scene depth testing preserves cover. The material has **opacity 1** but deliberately joins the transparent render queue at `renderOrder: 3`, with `depthWrite: false`. This lets ink coat alpha-blended wall/door illustrations. Moving it back to the opaque queue makes decorations such as the Bedroom 3 bear draw over the paint. No artwork-specific bounds, large surface lift or disabled depth test is used. Dynamic attachments update only when their displayed component pose changes. Projectile capsules and short trails are instanced by player color. Impact bursts are pooled and do not replay for a room's initial paint history. Sound is synthesized, starts after a user gesture and has an explicit mute button.

One steady-capacity server sample produced 641 shots over 80 seconds of held fire and retained exactly 600 marks. Its full JSON snapshot was 103,816 bytes before transport encoding/compression; regular paint updates send additions. Unlimited firing does not mean unbounded permanent paint history: the oldest marks are evicted at the cap.

## Regenerating source-derived assets

Run these commands from `packages/house`. On this Mac, the Blender executable is `/Applications/Blender.app/Contents/MacOS/Blender`.

```sh
blender --background --factory-startup ../../models/Huis_Oude_Terelststraat_15.blend --python scripts/closet-inventory.py -- --all --output /tmp/closet-evaluated-inventory.json
node scripts/closet-inventory.mjs --source /tmp/closet-evaluated-inventory.json
blender --background --factory-startup ../../models/Huis_Oude_Terelststraat_15.blend --python scripts/export-house.py -- --collision-only
node --import tsx scripts/prepare-door-targets.ts
```

The Python audit must evaluate actual mesh vertices, including curves. Old audits using curve `bound_box` values can produce enormous handle boxes and broken cupboard geometry. Regenerate the audit after source changes; do not trust a leftover file merely because its name matches an example command. This task used the evaluated `/tmp/closet-all-objects.json` audit as its source.

Put curated motion, attachments, source exclusions and structural relief changes in the generator as well as the generated manifest. A manifest-only edit will disappear on regeneration. Changing source exclusions requires a collision export. Shared generated board changes are consumed directly by both renderer and runtime collision.

Room door source changes use `scripts/export-doors.py`. Full house exports have additional texture, window, backface and lighting preparation steps documented in the [house README](../../packages/house/README.md). Do not overwrite the optimized or GPU house with an unprepared source export.
